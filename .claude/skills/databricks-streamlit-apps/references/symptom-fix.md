# Symptom → Fix register

**Check here FIRST when anything breaks.** Every row was hit (or narrowly avoided) shipping a real
Streamlit app on Databricks Apps. Ordered by how often it bites.

| Symptom | Root cause | Fix |
|---|---|---|
| App crashes on start: `Error: Invalid value for '--server.port' … '${DATABRICKS_APP_PORT:-8000}' is not a valid integer` | Apps exec's the `command:` array **without a shell**, so `${VAR}` is passed literally | Wrap in a shell: `command: [bash, -c, "streamlit run app.py --server.port ${DATABRICKS_APP_PORT:-8000} --server.address 0.0.0.0 --server.headless true"]` |
| 502 Bad Gateway, app "runs" but never reachable | Bound to `localhost`/`127.0.0.1` or a hardcoded port | Bind `--server.address 0.0.0.0` and `--server.port ${DATABRICKS_APP_PORT:-8000}` |
| First `bundle deploy` uploads thousands of files / is slow | Local `.venv/` + `__pycache__` swept into the bundle | Add `sync.exclude: [".venv/**","**/__pycache__/**","*.pyc"]` to `databricks.yml` **and** a `.gitignore`; delete `.venv` before deploy |
| `databricks apps deploy` → `Cannot deploy app … it is not in RUNNING state. Please start the app first` | Brand-new app's compute isn't started yet | `databricks apps start <name> --profile <p>` first, wait for compute ACTIVE, then `apps deploy` |
| Lakebase: `BadRequest: Database instance 'projects/.../endpoints/primary' not found` on EVERY page | Minting the token via the SDK's `w.database.generate_database_credential(instance_names=[...])` — that's the **legacy Provisioned** API and 404s the Autoscaling endpoint path | Mint via the Autoscaling REST call the CLI uses: `w.api_client.do("POST","/api/2.0/postgres/credentials", body={"endpoint": ENDPOINT_PATH})` → `.token`. Do NOT use `w.database.generate_database_credential`. Confirm the exact call with `databricks postgres generate-database-credential <ep> --debug` |
| Lakebase: `password authentication failed` / `permission denied for schema` after ~1h uptime | The OAuth token used as the PG password expired (tokens live ~1h) | Cache the token ~55 min; refresh on expiry AND on `OperationalError`/`InterfaceError`; reconnect. Never treat it as a static secret |
| Genie tool / warehouse query → `PERMISSION_DENIED: No access to <catalog>.<schema>.<table>` on a NEW app | The new app has its OWN service principal (≠ any app you granted before); it lacks UC SELECT/USE on the source catalog | Grant the NEW app's SP: `GRANT USE CATALOG ON CATALOG c TO \`<sp-client-id>\``, `USE SCHEMA`, `SELECT`. If you lack MANAGE on that catalog, an owner/admin must run it. Get the SP id from `databricks apps get <name>` → `service_principal_client_id`. Design so catalog-dependent features (forecast, Genie) degrade gracefully when the grant is pending |
| Lakebase: `permission denied for schema <x>` on a deployed app that worked locally | You dev'd locally first, so YOUR user creds own the schema; the app SP can't touch it | Deploy-first so the SP owns it, OR (cleaner) create + `GRANT` the schema to the SP client-id explicitly up front |
| `WorkspaceClient()` / `Config()` → `cannot configure default credentials` locally | No profile in the environment | Set `DATABRICKS_CONFIG_PROFILE=<name>` (or run with the profile). In a deployed app it's automatic (SP env vars) — never add a token |
| Serving `serving_endpoints.query(...)` → 400 / `endpoint not found` | Endpoint isn't a chat model, or wrong name, or SP lacks CAN_QUERY | Pick a READY `llm/v1/chat` endpoint from `serving-endpoints list`; declare it as a `serving_endpoint` resource with `permission: CAN_QUERY` |
| LLM call "works" but returns empty / your parse yields nothing | Reading the wrong field of the response object | Read `resp.choices[0].message.content`. (If you ever use the in-process AppKit handle instead, that one wraps in `{ok,data}` — but the SDK `serving_endpoints.query` returns the completion directly) |
| Genie tool "query failed" with no detail, or hangs | Early-exited before a terminal status, or didn't surface Genie's error | Poll `get_message` until status ∈ {COMPLETED, FAILED, CANCELLED, QUERY_RESULT_EXPIRED}; on FAILED read `m.error.error`; ~2s interval, ~5min budget |
| `st.dataframe(..., on_select=...)` throws / selection is empty | Wrong Streamlit version or missing `selection_mode` | Streamlit ≥1.35 for selections; set `on_select="rerun"` + `selection_mode="single-row"`; read `event.selection.rows` |
| "Where's the click action?" — a detail dialog/drawer never opens even though the row looks selected | `st.dataframe` row-select fires ONLY when the user ticks the **left-edge checkbox**; a plain **cell click** just highlights the cell and does nothing. Users (and reviewers) expect a whole-row click like a normal web table — Streamlit has no such thing | Don't make dataframe row-select the ONLY way in. Add an explicit control: a `st.selectbox` of items + a primary `st.button("Analyze ▸")` that opens the `@st.dialog`. Keep the checkbox path as a bonus (`if button_clicked: open(picked)` `elif event.selection.rows: open(sel)`). State it in the caption so the affordance is obvious |
| Streamlit reruns wipe the streamed AI text every interaction | Streaming result not persisted; re-streams (or blanks) on every widget change | Cache the finished result in `st.session_state[key]`; only stream when the key is missing or the user hits "Re-run" |
| Numbers/writes vanish after an action, UI shows stale queue | Streamlit didn't rerun after the write | Call `st.rerun()` after a successful `execute()`; KPIs/queue re-query from Lakebase (the Streamlit "live cascade") |
| `ai_forecast` returns nothing | Not enough history, or wrong `time_col`/`value_col`, or comparing across grains | Verify the base `TABLE(SELECT ts AS ds, val AS y …)` returns rows first; `time_col=>'ds'`, `value_col=>'y'`, `horizon => <date/int>` |
| `psycopg` connect hangs on macOS local dev | `getaddrinfo` on long Lakebase hostnames | Pass `connect_timeout`; if it persists, resolve the IP with `dig` and pass `hostaddr=` alongside `host=` (for TLS SNI) |
| Empty-string `''` fails inserting into a numeric column | Source data has `''` where a number is expected | Coerce `'' → NULL` before insert |
| `bundle validate` warns `required field "name" is not set` on genie_space | Genie resource needs a display `name` too | Add `name: <space display name>` alongside `space_id:` in the `genie_space` resource |
| Bundle deploy: `Unexpectedly failed to update app's compute size. Please try again later.` | Transient Apps control-plane hiccup (not your code) | Re-run `bundle deploy`; it succeeds on retry. Files already uploaded |
| Headless screenshot of the deployed app shows a login page | Databricks Apps gate on SSO; headless Chrome has no cookie | Expected. Verify the data layer as the SP via psql/CLI + `apps logs`; view the UI in a logged-in browser |

## Debugging workflow
1. `databricks apps get <name> --profile <p> -o json` → check `app_status.state` (RUNNING?) + `compute_status.state`.
2. `databricks apps logs <name> --tail-lines 100 --profile <p>` → look past the `[BUILD]` pip lines for the
   `[APP]` traceback or the Streamlit start banner. The real error is almost always one `[APP]` line.
3. If it's data, reproduce the exact SQL via `psql` (Lakebase) or the CLI (warehouse) as the SP identity —
   don't guess from the Python stack.
